# Module Starter Checklist (Cloudflare + AI Rail)

Use this checklist in each module repo.

Status labels:

- `[ ]` not started
- `[-]` in progress
- `[x]` complete

## 1. Repo Baseline

- [ ] `agent-docs/` exists.
- [ ] `wiki/` exists.
- [ ] `o-global/` exists with `DOSSIER.md` and `BRIEF.md`.
- [ ] `README.md` includes local run + deploy steps.

## 2. Runtime and Routing

- [ ] Cloudflare worker entrypoint exists (`src/index.ts` or equivalent).
- [ ] `GET /.well-known/airail-module.json` implemented.
- [ ] `GET /health` implemented.
- [ ] `GET /embed` (or `/`) implemented for shell preview.
- [ ] Module works under shell route prefix `/modules/<module-id>`.
- [ ] Module works under shell embed prefix `/modules/<module-id>/embed`.
- [ ] Asset and API URLs are path-prefix safe (no hard-coded root assumptions).

## 3. Auth Integration

- [ ] Auth middleware verifies JWT signature via JWKS.
- [ ] `iss`, `aud`, `exp`, `nbf` checks enforced.
- [ ] Claims checks enforced (`account_id`, `account_type`, entitlements/scopes).
- [ ] `401` and `403` behavior tested.
- [ ] Dev bypass exists and is disabled in non-local env.

## 4. Manifest Quality

- [ ] `id` uses canonical slug.
- [ ] `app_url` points to real deployed module URL.
- [ ] `embed_url` points to embeddable route.
- [ ] `health_url` points to health endpoint.
- [ ] `version`, `auth_mode`, `tags` included.

## 5. Environment and Secrets

- [ ] `wrangler.toml` contains `staging` and `production` environments.
- [ ] `.dev.vars.example` includes local-only variables.
- [ ] Required secrets documented in `agent-docs/`.
- [ ] No secrets committed to repository.

## 6. API and Error Contract

- [ ] Protected APIs return structured JSON errors.
- [ ] Error payload includes stable `error` code/message.
- [ ] `X-AIRAIL-Request-Id` forwarded/logged.
- [ ] No stack traces or secrets in responses.

## 7. CORS, CSP, and Embed Safety

- [ ] CORS restricts origins in staging/prod.
- [ ] `Authorization` header is allowed.
- [ ] `frame-ancestors` allows shell domains.
- [ ] No wildcard production frame policy.

## 8. Observability

- [ ] Structured logs include status/duration/request id.
- [ ] Health checks monitored (at minimum via cron or external monitor).
- [ ] Module emits clear startup/version logs.

## 9. AI Rail Shell Integration

- [ ] Module manifest URL added to `AIRAIL_MODULE_MANIFEST_URLS`.
- [ ] Module appears in `Modules` tab.
- [ ] `Open Module` works.
- [ ] `Embed Preview` works.
- [ ] Admin gating behavior verified.
- [ ] Route-based open path works (`/modules/<module-id>`).
- [ ] Route-based embed path works (`/modules/<module-id>/embed`).

## 10. Acceptance Tests (Smoke)

Run and capture output:

- [ ] `curl <module-url>/health`
- [ ] `curl <module-url>/.well-known/airail-module.json`
- [ ] Protected endpoint without auth returns `401`.
- [ ] Protected endpoint with wrong claims returns `403`.
- [ ] Protected endpoint with valid JWT returns `200`.
- [ ] Path-proxied route smoke test passes (`/modules/<module-id>`).
- [ ] Path-proxied embed smoke test passes (`/modules/<module-id>/embed`).

## 11. o-global Handoff

- [ ] Kickoff docs generated by repo AI:
  - `o-global/DOSSIER.md`
  - `o-global/BRIEF.md`
- [ ] Unknowns explicitly marked as `UNKNOWN`.
- [ ] Objectives are measurable, quantified, and timed.
- [ ] Downstream consumers are listed for tool/infra modules.

## 12. Final Signoff

- [ ] Module passes `MODULE_PLATFORM_CONTRACT.md`.
- [ ] Deployment runbook exists.
- [ ] Rollback plan documented.
- [ ] Owner and on-call contact documented.
